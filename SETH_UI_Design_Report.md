# Seth Explorer UI Design Report
This document is the English-normalized version of the original design proposal for Seth Explorer.
## Design Goals
- Build a fast, trustworthy, data-first explorer experience.
- Keep the visual language dark, clean, and consistent with the Seth brand.
- Improve readability, interaction feedback, and navigation clarity before adding decorative complexity.
## Core Recommendations
### Visual System
- Use a restrained dark palette with a clear Seth primary accent.
- Separate primary values, labels, and technical identifiers more aggressively.
- Prefer a dedicated monospace font for hashes, addresses, and machine-oriented values.
### Key UI Areas
- Dashboard: strengthen the hierarchy of summary cards and realtime lists.
- Tables: improve hover feedback, density, and method/status affordances.
- Detail pages: add clearer grouping, Prev/Next navigation, and raw-data access.
- Empty states: standardize explanatory copy and actionable CTAs.
- Status surfaces: make indexing and shard health understandable at a glance.
### Interaction Principles
- Favor lightweight, dependable motion over heavy effects.
- Ensure copy actions, filters, tabs, and state changes provide immediate feedback.
- Keep skeletons and loading placeholders aligned with real page structure.
## Delivery Priority
1. Fix trust-breaking issues such as inconsistent counters, empty states, and misleading status messaging.
2. Normalize shared UI patterns such as tables, cards, badges, and empty states.
3. Add secondary enhancements such as richer previews, advanced search affordances, and deeper data visualization.
